### 一、选择题


1. ::question{#choice-1 number="1"}

   在数据库中，使用:choice-slot{}语句为用户授权。

   :::choices{#options-choice-1 mode="single"}

   - :option[A]{#a} REVOKE
   - :option[B]{#b} GRANT
   - :option[C]{#c} INSERT
   - :option[D]{#d} CREATE

   :::

   :::reference

   ::correct{input="options-choice-1" option="b"}

   `GRANT`把权限授予用户或角色，`REVOKE`回收权限；`INSERT`和`CREATE`不是授权命令。

   :::

   - :option[B]{#b} 可以为一个用户授予多个角色
   - :option[C]{#c} MySQL角色授予用户后立即生效
   - :option[D]{#d} 删除角色可回收用户的角色

   :::

   :::reference

   ::correct{input="options-choice-2" option="c"}

   角色是一组权限的命名集合，一个用户可以拥有多个角色。角色被授予用户后不会自动成为当前会话的启用角色，通常还需设置默认角色或执行`SET ROLE`；删除角色则会使该角色带来的权限失效。

   :::

5. ::question{#choice-5 number="5"}

   使用MySQL时，想要实时记录数据库中所有修改、插入和删除操作，需要启用:choice-slot{}。

   :::choices{#options-choice-5 mode="single"}

   - :option[B]{#b} 通用日志

   :::

6. ::question{#choice-6 number="6"}

   :::choices{#options-choice-6 mode="single"}

   - :option[B]{#b} 区别

   - :option[D]{#d} 二次

   :::

   :::reference

   ::correct{input="options-choice-6" option="c"}

   :::

8. ::question{#choice-8 number="8"}

   数据库管理系统通常提供授权功能来控制不同用户访问数据的权限，这主要是为了实现数据库的:choice-slot{}。

   :::choices{#options-choice-8 mode="single"}

   - :option[A]{#a} 可靠性
   - :option[B]{#b} 一致性
   - :option[C]{#c} 完整性
   - :option[D]{#d} 安全性

   :::

   :::reference

   ::correct{input="options-choice-8" option="d"}

   授权限制谁可以访问哪些对象并执行哪些操作，属于数据库安全性；完整性关注数据正确性，一致性关注状态约束，可靠性更侧重系统持续服务。

   :::

9. ::question{#choice-9 number="9"}

   事务的隔离性是指:choice-slot{}。

   :::choices{#options-choice-9 mode="single"}

   - :option[A]{#a} 事务中包括的所有操作要么都做，要么都不做
   - :option[B]{#b} 事务一旦提交，对数据库的改变是永久的
   - :option[C]{#c} 一个事务内部的操作及使用的数据对并发的其他事务是隔离的
   - :option[D]{#d} 事务必须是使数据库从一个一致性状态变到另一个一致性状态

   :::

   :::reference

   ::correct{input="options-choice-9" option="c"}

   隔离性要求一个事务的中间状态和未提交修改不被其他并发事务任意观察；原子性描述全做或全不做，持久性描述提交结果长期保留。

   :::

10. ::question{#choice-10 number="10"}

    事务的持久性是指:choice-slot{}。

    :::choices{#options-choice-10 mode="single"}

    - :option[A]{#a} 事务中包括的所有操作要么都做，要么都不做
    - :option[B]{#b} 事务一旦提交，对数据库的改变是永久的
    - :option[C]{#c} 一个事务内部的操作及使用的数据对并发的其他事务是隔离的
    - :option[D]{#d} 事务必须是使数据库从一个一致性状态变到另一个一致性状态

    :::

    :::reference

    ::correct{input="options-choice-10" option="b"}

    持久性表示事务成功提交后，其结果即使发生系统故障也应通过日志和恢复机制保留下来；事务提交后不应被随意回退。

    :::

11. ::question{#choice-11 number="11"}

    若系统在运行过程中，由于某种硬件故障，使存储在外存上的数据部分损失或全部损失，这种情况称为:choice-slot{}。

    :::choices{#options-choice-11 mode="single"}

    - :option[A]{#a} 事务故障
    - :option[B]{#b} 系统故障

    - :option[D]{#d} 运行故障

    :::

    :::reference

    ::correct{input="options-choice-11" option="c"}

    外存数据部分或全部损坏属于介质故障，需要装载备份并用日志重做；事务故障和系统故障通常不直接意味着磁盘介质永久损坏。

    :::

### 三、简答题


24. ::question{#short-1 number="1"}

    简述数据库安全控制的基本方法。

    :::reference

    （1）用户标识和鉴定：记录合法用户的标识，由系统核实用户身份后才提供系统使用权。
    （2）用户存取权限控制：确保只有获得合法授权的用户才能访问数据库，并阻止未授权人员访问数据。
    （3）定义视图：视图机制把要保密的数据对无权存取这些数据的用户隐藏起来，从而自动地对数据提供一定程度的安全保护。
    （4）数据加密：为了防止数据窃取问题，人们可对数据进行加密。
    （5）审计：把用户对数据库的所有操作自动记录下来，存放在审计日志中。

    :::

25. ::question{#short-2 number="2"}

    简述系统权限与对象权限的区别。

    :::reference

    系统权限表示用户对数据库模式的操作权限，即创建数据库或者创建数据库中的其他内容所需要的权限类型。系统权限针对的主要是数据库结构。
    对象权限是授予数据库用户对特定数据库中的表、视图和存储过程等对象的操作权限，它决定了能对表、视图等数据库对象执行哪些操作，相当于数据库操纵语言的语句权限。对象权限针对的是用户数据。

    :::

26. ::question{#short-3 number="3"}

    什么是事务，有哪四个性质？

    :::reference

    事务是数据库系统中执行的一个工作单位，它是由用户定义的一组操作序列。事务具有原子性、一致性、隔离性和持久性四个性质。

    :::

27. ::question{#short-4 number="4"}

    MySQL开启二进制日志有哪些好处？

    :::reference

    MySQL二进制日志文件记录所有用户对数据库的操作（除SELECT语句之外）。当数据库发生意外时，通过此文件可以查看一定时间段内用户所做的操作，结合数据库备份技术即可实现数据库还原。因此，在数据库发生故障时，利用二进制日志能够最大可能地更新数据库。

    :::

28. ::question{#short-5 number="5"}

    为什么要进行数据库备份与数据库还原？

    :::reference

    数据永久丢失是数据库用户不能接受的，数据库管理系统应采取措施防范数据永久丢失。数据库备份就是将数据库中的数据以及保证数据库系统正常运行的有关信息保存起来，以备数据库恢复时使用。系统发生介质故障，数据库遭到破坏，可以将后备副本重新装入，再利用事务日志重做最后一次备份之后提交的所有事务，将数据库恢复到故障前的一致性状态。

    :::
