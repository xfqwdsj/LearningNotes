## 定义

::section{#definition slot="knowledge.definition"}

数据库安全的目标是防止数据被非法访问、泄露、篡改或破坏。安全措施需要与操作系统、网络、服务器物理环境和管理制度共同配合。

## 安全控制方法

- **用户标识与鉴别**：确认用户身份，可采用静态口令、动态口令、生物特征或硬件凭证。
- **存取权限控制**：先定义用户能对哪些对象执行什么操作，再在访问时检查权限。
- **视图限制**：隐藏用户无权查看的行、列，并允许把权限授予视图而不是基础表。
- **数据加密**：把明文转换为密文，即使存储介质或传输内容泄露也不能直接读取。
- **审计**：记录访问者的身份、时间、操作、数据对象以及修改前后的值。

安全级别越高通常意味着更多验证、授权或性能开销，需要按数据敏感程度选择措施。

## 自主与强制存取控制

::section{#access-control}

**自主存取控制（DAC）** 让对象所有者或管理员为用户授予不同权限，并允许受控转授权。常见`GRANT`、`REVOKE`属于这一类。

**强制存取控制（MAC）** 给数据和用户分别设置安全级别，只有满足级别规则的用户才能访问对象。它更严格，适用于密级分类固定而敏感的场景，但并非所有DBMS都支持。

权限由“数据库对象”和“操作类型”共同组成：

- **系统权限**作用于模式和数据库级对象，例如创建数据库、表、视图或索引。
- **对象权限**作用于具体表、视图、字段或存储例程，例如查询、插入和更新。

## 用户、权限与角色

::section{#accounts}

创建用户时必须同时考虑账户名和允许连接的主机：

```sql
CREATE USER IF NOT EXISTS teacher1@'%'
IDENTIFIED BY 'example-password';
```

授予权限：

```sql
GRANT SELECT, UPDATE ON teach.teacher
TO teacher1@'%';

GRANT SELECT (tno, tname) ON teach.teacher
TO teacher2@'localhost';
```

`WITH GRANT OPTION`允许被授权用户继续把该权限授予他人。回收权限使用：

```sql
REVOKE UPDATE ON teach.teacher FROM teacher1@'%';
```

角色是权限集合。创建角色、授予权限、分配给用户后，用户需要按DBMS的机制激活角色才能实际使用：

```sql
CREATE ROLE teacher;
GRANT SELECT ON teach.student TO teacher;
GRANT teacher TO teacher1@'%';
SET DEFAULT ROLE teacher TO teacher1@'%';
```

删除用户不一定删除其创建的数据库对象，但对象的定义者属性可能影响后续维护，因此删除账户前应检查对象所有权。

## 审计与最小权限

::section{#least-privilege}

审计日志能追踪操作，但会带来存储和维护成本。高敏感数据应记录必要的登录、授权、结构变化和数据修改活动。

权限设计应遵循最小权限原则：账户只获得完成当前职责所需的对象和操作，临时提权应尽量限定在短会话内。应用不应频繁使用拥有全部权限的超级管理员账户。
