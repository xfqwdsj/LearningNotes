# 发布前检查

任何`git push`、部署、发布产物或上传静态文件等会把未公开内容带出本机的操作前，本技能规定的检查必须全部通过；失败或存在未判定事项时停止。

## 流程

1. 先看[当前CI工作流](../../../.github/workflows/site.yaml)。以其中当前定义的检查、环境和发布条件为唯一事实源，按原步骤复现，不在技能或报告中另立一份检查清单。
2. 检查待公开提交、修改和未跟踪文件的范围。确认没有混入私有内容、凭据、临时文件或无关修改，并说明实际覆盖的公开与私有范围。
3. 运行CI定义的检查。未运行、被跳过、失败或环境与CI不一致的项目不能算通过。
4. 推送前完成本地CI等价检查。推送后、部署或其他公开操作前，确认CI对同一提交通过；其他提交的结果不能代替。

## 空格扫描警告

当前检查产生的每条空格候选警告都必须主动处理：

- 定位到具体文件、行和AST或渲染上下文，判断它是否属于可见文本中的中西文间距。
- 应当修正时，使用当前文档规定的共享规则和流程；规则不覆盖的结构在确认语义后手动编辑。
- 不修正时，记录它为何属于代码格式、标点、元数据、结构性分隔或其他不适用场景。不得静默忽略、删除警告或扩大忽略范围。
- 完成判断后重新运行相关检查，确保没有待修正项或未解释警告。

## 阻断条件

以下任一情况阻止推送、部署和公开：

- CI检查失败、超时、未运行或被错误跳过。
- 空格候选尚未逐项判定，或判定需要修改但尚未完成。
- 公开与私有范围不明确，或待发布提交与已检查提交不一致。
- 推送后、部署前缺少同一提交的CI通过结果。

最终报告列出检查的提交、实际结果、内容范围、每条空格警告的处理结论，以及尚存的CI或部署限制。
