# 维护学科与课程

操作方法与字段契约见 [维护学科与课程](../../../docs/writing/taxonomy.md)；文章位置见 [内容组织](../../../docs/writing/content.md)。分类名称、介绍和标签等可见文本的中西文间距遵循 [语法文档](../../../docs/writing/syntax.md#中西文间距)。

## 常见误区

- 在UI消息或组件里新增分类名称、逐ID图标映射，或为同一课程在不同集合复制定义。显示信息来自专属入口，集合目录继承它。
- 将课程ID当成全站唯一，搜索或展示时遗漏所属学科。课程身份包含学科；同名ID不代表同一课程。
- 只改文章路径，不建立对应入口；或者为了改显示名称而重命名身份。先区分元数据编辑与路径迁移，核对已有链接。
- 在镜像目录添加标题、图标或阅读正文，导致信息来源分裂。入口说明写在专属入口，知识点与任务正文仍归其内容类型。
- 把学科做成所有内容的隐形根节点，或在课程页高亮学科入口。内容类型与学科是平行浏览维度，跨集合链接明确目的地。
- 为接入统一入口而改写文章面包屑。入口负责浏览，面包屑表示当前页面的真实目录层级。
- 将私有定义移到公开消息包，或在译文中更换图标与排序。检查默认语言定义、回退和产物范围，而不只看当前页面是否有名字。
- 移动入口正文后保留失效的相对链接，或给缺失章节填上无关目录链接。核对真实目标，未写内容可以保留普通文字。
