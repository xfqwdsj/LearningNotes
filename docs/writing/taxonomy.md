# 维护学科与课程

学科和课程是可扩展的内容分类。名称、介绍、图标、顺序和入口正文集中写在专属`_index.mdx`中；界面按身份直接读取这份元数据。

## 定义位置与身份

```text
content/subjects/_index.mdx
content/subjects/<学科>/_index.mdx
content/subjects/<学科>/<课程>/_index.mdx
```

学科ID取自目录名；课程身份由“学科ID＋课程ID”组成。两者使用小写字母、数字和连字符，不在front matter重复写ID。不同学科可以使用相同课程ID，它们仍是不同课程。

这些文件是分类入口定义，生成`/subjects/<学科>/`与`/subjects/<学科>/<课程>/`页面，分别汇集课程和相应的内容集合。知识点、课程笔记与任务的路径由[内容组织](content.md#路径与身份)定义；入口页负责分类元数据与阅读指引。

自由文章默认使用`general`学科；存在自由文章时需要保留这项定义，显示名称可以修改。

## 元数据

学科入口示例：

```mdx
---
title: 学科
description: 说明。
icon: book-open
order: 1
---

## 标题

正文内容。
```

课程入口示例：

```mdx
---
title: 课程
description: 说明。
icon: book-open
order: 1
---

## 标题

正文内容。
```

| 字段 | 约定 |
| --- | --- |
| `title` | 必填，显示名称；可使用站点支持的行内公式 |
| `description` | 必填、非空，用于入口与卡片的介绍 |
| `icon` | 可选，[Lucide图标](https://lucide.dev/icons/)的小写连字符名称，默认`book-open` |
| `order` | 可选，数字越小越靠前，默认1000 |

学科之间、同一学科的课程之间按顺序排列；相同顺序按身份自然排序。图标在构建时从已安装的Lucide包读取并生成SVG，只把使用到的图标带入产物。前端消费生成的SVG；拼错名称使准备失败。

名称和介绍直接使用本地化的内容元数据。`messages`的固定界面文案包保持通用；每个分类通过入口元数据携带自己的名称和介绍。

## 新增或调整

新增学科时，先建立学科入口；新增课程时，在所属学科下建立课程入口。目录已有定义时更新原文件，不按“知识点／笔记／任务”各建一份。

然后按内容组织契约放置文章及集合目录。文章所属学科、课程仍从路径推导，准备阶段校验对应入口是否存在。未定义的身份会报错，不会以原始目录名悄悄显示在页面上。

修改显示名称、介绍或图标只编辑入口元数据，目录ID保持稳定。修改ID属于路径迁移，需要同时处理文章归属、内部链接、已有入口和既有外部链接。

入口正文可以编写阅读路线、教材说明、课程安排以及链接，也可以按[引入语法](syntax.md#语义板块与引入)引用已有知识点。原始知识、证明和交互演示放在[知识点](knowledge.md)中，练习与作答使用任务内容；入口不替代这些内容类型。链接优先写站点的完整路径，避免在移动入口时改变相对路径含义。

## 集合目录如何复用

以下集合目录自动复用学科或课程的显示名称、图标和默认顺序：

- `knowledge/<学科>/_index.mdx`
- `courses/<学科>/_index.mdx`与`courses/<学科>/<课程>/_index.mdx`
- `tasks/<学科>/_index.mdx`与`tasks/<学科>/<课程>/_index.mdx`

目录文件仍保留，用来明确内容层级；无需覆盖信息时可写：

```mdx
---
{}
---
```

这些镜像目录的名称与图标继承专属入口。目录可以通过`description`说明当前集合的范围，通过`order`明确调整该集合中的顺序；省略时继承入口定义。阅读指引正文写入专属入口。

其他目录，例如知识点下更深的分类、任务类型目录，按内容组织契约提供自己的标题与描述。课程身份来自`content/subjects/<学科>/<课程>/_index.mdx`。

## 公开定义与私有内容

翻译沿用内容语言目录，例如`content/<language>/subjects/<subject>/<course>/_index.mdx`。译文保持相同身份，写本语言的名称、介绍和可选正文；默认语言的定义必须存在。未提供对应语言时按现有内容语言回退规则读取。图标和排序属于同一实体，译文省略这些字段；显式填写时必须与默认定义一致。

学科与课程定义及其译文统一存放在公开仓的`content/subjects/`。私有仓沿用这些公开身份，私有构建读取公开taxonomy。准备阶段拒绝私有仓中的`content/subjects/`定义。公开入口文案描述学科或课程本身；私有链接、材料名称和下级内容清单留在私有内容中。界面名称从入口元数据读取，`messages`保持通用界面文案。

文章、搜索结果与导航使用相同的分类身份和本地化名称；课程名称按学科查找。私有首页的内容合并不改变公开内容索引的范围。

## 浏览与发现

内容类型与学科是两种并列的浏览方式。顶栏直接进入课程、知识点、学习任务和文章；首页将这四类内容作为一组，与学科浏览并列。学科页区分内容入口与课程概览，跨到内容集合时标明目的地；内容页的“其他浏览方式”提供对应学科总览和课程概览，不暗示它们是当前目录的父级。

面包屑保持当前页面的真实层级。课程笔记表示“课程资料 → 学科 → 课程 → 文章”，学科入口表示“学科 → 具体学科 → 课程”，不把文章所属集合伪装成入口目录。

根索引提供`/taxonomy.json`的发现链接；该文件列出分类身份、名称、介绍、图标名、入口及Markdown地址，不携带入口正文。完整正文按页面或Markdown地址读取。准备、构建和预览命令见[运维文档](../operations.md#开发)。

完成修改后检查入口名称与图标、集合卡片、面包屑、搜索中的课程区分、语言回退及公开／私有范围。包含正文链接时检查目标存在，并将尚无内容的章节保留为普通文字。
